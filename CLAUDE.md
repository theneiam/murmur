# Murmur — notes for Claude Code

Murmur is a menu-bar, push-to-talk dictation app for macOS 14+ / Apple Silicon. Hold a hotkey → record → release → transcribe locally with WhisperKit → insert text at the cursor in the frontmost app. It works end to end as of 2026-09-07 and is in daily use by the owner. Full background is in README.md; this file is the operational cheat-sheet.

## Build & run

```bash
xcodegen generate          # only needed after editing project.yml (regenerates Murmur.xcodeproj, Murmur/Info.plist, Murmur/Murmur.entitlements)
xcodebuild -project Murmur.xcodeproj -scheme Murmur -configuration Debug build 2>&1 | tail -40
open build/DerivedData/Build/Products/Debug/Murmur.app   # or ⌘R in Xcode
log stream --predicate 'subsystem == "com.yevhen.murmur"' --level debug   # app logs
```

Release DMG for personal use: Release `xcodebuild` + `scripts/make-dmg.sh <app> <dmg>`. Signed+notarized distribution: `scripts/release.sh` (needs `TEAM_ID`, `NOTARY_PROFILE`; see README) → `build/release/`, separate from the debug `build/DerivedData`.

Quit any running Murmur before launching a new build — two instances would both install event taps.

## Gotchas (learned the hard way)

- `Murmur/Info.plist` and `Murmur/Murmur.entitlements` are **generated by XcodeGen and git-ignored**. If they go missing, run `xcodegen generate`. Don't hand-edit them; edit `project.yml`.
- **AVAudioEngine stops itself on device reconfiguration.** Opening a Bluetooth input (AirPods) switches the headset from its music profile to its headset profile, which changes the input format mid-start; the engine stops and posts `AVAudioEngineConfigurationChange`, and `StartIO … error 35` / "Abandoning I/O cycle because reconfig pending" appear in the console. `AudioRecorder` observes the notification and rebuilds the engine, and a 1.5 s first-buffer watchdog restarts it up to 3 times (root cause found and fixed 2026-09-08; an earlier `killall coreaudiod` only appeared to help). Keep both when touching the recorder. Symptom without them: "Recording stopped … with no audio from <device>". If it ever recurs with the built-in mic *and* QuickTime also fails, then it is the system: `sudo killall coreaudiod`. If the mic grant no longer matches the app's signature after a re-sign, `AVCaptureDevice.authorizationStatus` still says authorized while coreaudiod refuses IO — `tccutil reset Microphone com.yevhen.murmur`, relaunch, accept the prompt.
- **Accessibility permission is bound to the code signature.** If the app is rebuilt with a different signing identity, macOS silently stops trusting it (the toggle stays on, `AXIsProcessTrusted()` says false): remove Murmur from System Settings → Privacy & Security → Accessibility with the − button and re-add it. `DEVELOPMENT_TEAM` comes from the git-ignored `Config/Local.xcconfig` (copy `Config/Local.xcconfig.example`); the owner's is set locally. Never put it in `project.yml` (it is a public repo) or only in Xcode's Signing tab (lost on the next `xcodegen generate`). Without it the build silently becomes ad-hoc (`codesign -dvv` shows `Signature=adhoc`) and every rebuild needs a fresh grant. Check with `codesign -d -r- Murmur.app`: the designated requirement should name the Apple Development certificate, not a `cdhash`.
- Not sandboxed on purpose: global CGEvent taps and AX writes into other apps require it. Hardened runtime is on; the only entitlement is `audio-input`.
- **The CGEvent tap runs on its own thread** (`HotkeyManager`, thread `com.yevhen.murmur.event-tap`) so a busy main thread can't stall keystrokes system-wide. The callback must still return in microseconds: it only runs the pure `TapState.handle` under a lock and posts events to the main queue. Never touch AppKit or main-actor state from `HotkeyManager.handle`; `onPress`/`onRelease`/`onCancel` and capture completions are always delivered on main.
- **Tests** (`MurmurTests`, hosted in the app): `xcodebuild test -project Murmur.xcodeproj -scheme Murmur -destination 'platform=macOS'`. `AppDelegate` skips all start-up work when `XCTestConfigurationFilePath` is set, so tests never install a second event tap next to a running Murmur. `DictationSession` (via fakes for its four seams), `ModelManager` (via `FakeEngine`), `TapState`, `TextPostProcessor`, `Hotkey`, settings decoding and `ModelManager.isCompleteBundle` are covered; keep new logic behind a seam or in a pure function.
- Modifier-only hotkeys match on `flagsChanged` using device-specific left/right bits (`Hotkey.deviceMask`) plus an exact match on the generic modifier bits. Key hotkeys are swallowed (return nil from the tap); modifier hotkeys are never swallowed.
- Murmur's own synthesized ⌘V carries `SyntheticEvents.tag` (`Support/SyntheticEvents.swift`) in `eventSourceUserData`; the tap ignores tagged events. Keep the tag on any new synthesized events.
- WhisperKit lives in the renamed package `argmax-oss-swift` (product `WhisperKit`; `import WhisperKit` re-exports `ArgmaxCore`). Do **not** add the `ArgmaxOSS` umbrella product — it pulls in TTSKit, which requires macOS 15.
- WhisperKit model naming trap: OpenAI's large-v3-*turbo* checkpoint is `openai_whisper-large-v3-v20240930[_626MB]`. The `_turbo` suffix on other variants means an encoder compute optimisation, not the turbo model.
- Model files: `~/Library/Application Support/Murmur/Models/models/argmaxinc/whisperkit-coreml/<variant>/`. The tokenizer is fetched from `openai/whisper-*` on the first load of each model and cached under `Models/tokenizers/`; after that everything is offline. First load of a model also triggers CoreML/ANE compilation (seconds for Small, minutes for larger).
- **`NSApp.delegate as? AppDelegate` is always nil.** With `@NSApplicationDelegateAdaptor`, `NSApp.delegate` is SwiftUI's private wrapper class, which is also named `AppDelegate`. Menu actions that used that cast did nothing, silently (found 2026-09-11). Open windows through `AppState.showOnboarding()` / `showStatistics()`; `AppWindowsTests` guards the cast.
- Swift 5.10 language mode, `SWIFT_STRICT_CONCURRENCY=minimal`. Closures handed to AppKit completion handlers are `@Sendable` — use `MainActor.assumeIsolated { }` inside them rather than touching main-actor state directly (see `StatusPanel.orderOut`).
- `UCKeyTranslate` takes plain `Int` lengths in Swift; `UniCharCount` is not exposed.
- Settings are JSON blobs in UserDefaults (`murmur.*` keys). Any struct stored there needs a tolerant `init(from:)` with `decodeIfPresent` (see `PostProcessingOptions`) so adding a field never wipes a user's settings.

| Dictation | `Dictation/DictationSession.swift`, `Dictation/DictationSeams.swift` | The push-to-talk pipeline (`idle → starting → recording → transcribing → inserting`), timeout, post-processing, insertion, sample insertion. Depends only on the seams `AudioCapturing`, `ModelProviding` (+ `ModelAvailability`), `TextInserting`, `DictationPresenting` and a `DictationConfig` snapshot; emits `DictationEvent`s. Fully covered by `DictationSessionTests` with fakes — add new pipeline behaviour here, with a test, not in AppState |
| App shell | `App/MurmurApp.swift` | `MenuBarExtra` + `Settings` scenes, `AppDelegate` (accessory policy, onboarding) |
| Hotkey | `Hotkey/Hotkey.swift`, `Hotkey/HotkeyManager.swift` | Model + display names; CGEvent tap, press/release/cancel, hotkey capture for Settings |
| Audio | `Audio/AudioRecorder.swift`, `Audio/AudioDevices.swift` | AVAudioEngine → 16 kHz mono Float32, level meter, max-duration auto-stop; CoreAudio device list |
| Speech | `Transcription/*` | `WhisperModel`/`TranscriptionLanguage` catalog, `TranscriptionEngine` protocol, `WhisperKitEngine` actor (one warm pipeline), `ModelManager` (download/load/status) |
| Insertion | `Insertion/*` | `StrategyInserter` (the `TextInserting` adapter; strategy over two `TextWriting` adapters, tested with fakes) → `AccessibilityWriter`/`AccessibilityInserter` (AX selected-text write + verification) or `PasteboardWriter`/`PasteboardInserter` (⌘V + clipboard snapshot/restore) |

## Product constraints (don't drift)

- Push-to-talk **only** — no toggle/hands-free mode, no streaming/partial results.
- No network at runtime except user-initiated model download (and the one-time tokenizer fetch). No accounts, telemetry, update checks. "Check for Updates…" and the Help links only open the browser (`SupportLinks`); keep it that way.
- No Dock icon (`LSUIElement`), no windows that steal focus while dictating; the indicator panel is non-activating.
- Text goes into other apps only; no editor UI of its own.
